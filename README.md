# NRG / INDEX

Коллективный тирлист энергетиков: сервер на Node.js + Express, база SQLite, личный кабинет и админ-панель. На главной — общий стол, рейтинг брендов (среднее оценок моделей) и рулетка.

## Стек

- Node.js 22, Express 5, better-sqlite3 (WAL), миграции через `PRAGMA user_version`
- Пароли — `scrypt` (N=32768, r=8, p=1, соль на пользователя), сравнение через `timingSafeEqual`
- Сессии — в БД (хранится SHA-256 от токена), cookie `httpOnly` + `SameSite=Lax`, `Secure` автоматически за TLS-прокси
- Защита API: обязательный заголовок `X-NRG-Request` + проверка Origin на изменяющих запросах, rate-limit логина
- ИИ (OpenRouter) и поиск фото (Wikimedia Commons) выполняются только на сервере — ключи не попадают в браузер
- Фронтенд — ванильный JS (`public/`), админка — `admin/`, без сборки

## Структура

```
server/          Express-приложение: app.js, db.js, auth.js, routes/, lib/
public/          Публичный сайт и кабинет (статика)
admin/           Админ-панель (отдаётся только ролям editor/admin)
scripts/         create-admin.js, optimize-assets.js (WebP + srcset для public/assets)
tests/           node:test — unit и интеграционные API-тесты
deploy/          systemd-юнит для сервера
```

## Локальный запуск

```bash
npm ci
npm test
DB_PATH=./data/nrg.db UPLOADS_DIR=./data/uploads PORT=3000 npm start
```

Ручная браузерная проверка сканера (отдельно от `npm test`): нужен установленный
Chrome / chrome-headless-shell. Обычные тесты и CI браузера не требуют.

```bash
CHROME_BIN=/path/to/chrome-headless-shell node scripts/check-live-scanner.mjs
```

Первый администратор:

```bash
npm run create-admin -- --username admin --name "Ваше имя"
```

Схема БД и базовые тиры создаются автоматически при первом запуске.

## Роли

- `admin` — всё: напитки, оценки, тиры, пользователи, настройки, журнал
- `editor` — напитки, оценки, публикация
- `user` — свои оценки и свои добавленные банки

Пользователей создаёт админ в панели: выдаётся временный пароль, при первом входе требуется сменить его.

**Фото банки — общее.** Заменить или убрать картинку может любой вошедший участник: так задумано, чтобы фото можно было легко починить (кривой ракурс, битая ссылка). Правка полей и удаление самой банки — только владелец, `editor` или `admin`. Каждая правка фото попадает в журнал и откатывается админом.

## Титулы месяца

В профиле возле имени видны ежемесячные титулы — просто текст, без иконок. Считаются автоматически за текущий календарный месяц: главный оцениватель (больше всех оценок), самый подробный (больше всех текста в отзывах), первооткрыватель (больше всех новых банок), голос стола и бунтарь (лучше и хуже всех совпал с мнением остальных), самый щедрый и самый строгий (средняя оценка). При равенстве титул получают все лидеры; в зачёт идут только активные публичные участники и опубликованные банки, а 1-го числа отсчёт начинается заново.

## ИИ

- Разбор текста — `{base}/chat/completions`, модель по умолчанию `openai/gpt-4o-mini`. Промпт запрещает модели придумывать мнение: отзыв и тир берутся только из сообщения автора, пустое поле лучше выдуманного.
- Голосовые — запись в браузере (MediaRecorder), распознавание на сервере через `{base}/audio/transcriptions`, модель по умолчанию `openai/whisper-large-v3-turbo`.
- Base URL (по умолчанию `https://openrouter.ai/api/v1`), ключ и обе модели настраиваются в админке → Настройки. Для OpenRouter аудио уходит JSON-ом (`input_audio`), для других OpenAI-совместимых API — multipart.
- Ассортимент по фото: в кабинете можно загрузить фото полки — Gemini (`gemini-3.8-flash`, настраивается в админке) распознаёт банки и вкусы, найденные в базе подтягивают фото и открывают оценку. Само фото не хранится.
- Штрих-код: в кабинете можно отсканировать EAN камерой или вставить код Честного знака (Data Matrix). Живой скан читает кадр локально: нативный `BarcodeDetector`, затем браузерный zxing-wasm (`public/vendor/zxing-wasm/`, грузится лениво; для бликующей крышки банки — Otsu-порог с инверсией), а как страховка — вендорный ZXing (`public/vendor/zxing.min.js`). Если локально не вышло, кадр уходит на серверный разбор (`POST /api/cabinet/ai/barcode-scan`, zxing-wasm + sharp) не чаще раза в 4 c. EAN и GTIN ищутся в Open Food Facts, для кодов маркировки дополнительно best-effort запрос в CRPT; найденное подставляет поля и фото, а сам код сохраняется у банки — повторный скан находит её сразу.
- Перерисовка фото — двух провайдеров, переключается в админке → Настройки. Gemini — зелёный хромакей и клиентская вырезка фона. OpenRouter — тот же ключ, что для STT (`/api/v1/images`), модель `openai/gpt-image-2.5-sunburst` (9:16, low, transparent, PNG): по умолчанию в запрос уходит только фото банки, а ракурс и матовость описывает промпт; фон не режется, стоимость берётся из `usage.cost` и видна на вкладке «Логи». Промпты обеих генераций настраиваются в админке → Настройки (поле показывает действующий текст; пусто = встроенный стандарт, кнопка «Сбросить промпты» возвращает оба). В промпте Gemini нужно сохранять требование зелёного фона (#00FF00), в промпте OpenRouter — прозрачного фона (transparent). Свой фото-шаблон можно загрузить в админке (PNG/JPEG/WebP, до 4 МБ, хранится в uploads как есть) — тогда он уходит вторым референсом, а «Сбросить шаблон» возвращает генерацию без шаблона.

## Журнал

Админка → Журнал: кто что сделал, по-русски, с разницей «было → стало». Большинство действий (напитки, оценки, тиры, пользователи, настройки кроме ключа) можно откатить; откат идёт по порядку — если объект менялся позже, сначала откатывается более свежая запись.

## Логи

Админка → Логи: каждый запрос к ИИ и STT (вид, модель, токены, цена, время) и серверные ошибки 5xx, в том числе сбои ИИ. Ошибки, которые не валят запрос (например, чистка расшифровки), тоже пишутся. Фильтр по ИИ и ошибкам, поиск по модели/сообщению.

## Деплой

Ветка `production` — точка деплоя. На push GitHub Actions запускает:

1. `Pre-deploy tests` — `npm ci` + `npm test` на self-hosted runner
2. `Deploy site` — `environment: production`, ждёт ручного апрува; дальше `npm ci --omit=dev`, dry-run миграций на временной БД, rsync в `/opt/nrgindex`, обновление systemd-юнита, рестарт, health-check `/api/health` и автоматический откат при провале

Одноразовая настройка в GitHub (Settings → Environments → New environment `production`): добавить себя в Required reviewers — тогда каждый деплой будет ждать ручного подтверждения.

Конфиг сервиса — `/etc/nrgindex.env`:

```
PORT=80
DB_PATH=/var/lib/nrgindex/nrgindex.db
UPLOADS_DIR=/var/lib/nrgindex/uploads
TRUST_PROXY=10.10.20.25    # IP обратного прокси; X-Forwarded-* принимаются только от него
COOKIE_SECURE=auto
SESSION_TTL_DAYS=90
SESSION_IDLE_DAYS=30
OPENROUTER_KEY=            # можно задать в админке (Настройки)
AI_BASE_URL=               # необязательно; в админке приоритетнее
```

systemd-юнит обновляется вручную: скопировать `deploy/nrgindex.service` в `/etc/systemd/system/`, затем `systemctl daemon-reload && systemctl restart nrgindex`. Деплой обновляет только код — у runner'а нет прав на изменение юнита.

Данные (БД и загрузки) лежат в `/var/lib/nrgindex` и в репозиторий не попадают.
